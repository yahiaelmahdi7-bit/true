## What to build
1. **Style card** — `python -m clipengine edit-style --campaign <id> --refs <dir>`: measures the refs (duration range, cut rate
   via scene detect, letterbox geometry via black-band detection, text density from frame sampling, loudness) and writes
   `<refs>/STYLE.json` (machine numbers the checks use) + `<refs>/STYLE.md` (human-readable house style, seeded from the read above).
2. **New preset E "Dark immersive"** (Yahia asked for "cool dark background, immersive text with editing"): footage letterboxed on a
   near-black field (subtle grain/vignette, optional slow 1.00->1.04 push-in), large condensed kinetic type living in the black
   bands — hook line in the top band, keyword pops / word-by-word in the bottom band, one campaign accent colour (PB Blake = the red
   from example "SEEN"). Text must never sit over a face. Presets A-D from the style read are also available.
   Text renderer: prefer motion-design's deterministic HTML->frames renderer for the text layer IF it can emit transparent frames at
   <= 2x realtime for a 45 s clip (composite with ffmpeg); otherwise Pillow cards with 3-4 pop-scale frames per word via the existing
   overlay path. Measure, pick, and record the numbers in result.md. Fonts: OFL-licensed only, bundle under Assets with the license.
3. **Edit plan** — `edit-plan --moment <id> --campaign <id>` -> `EDL.json` per edit: in/out, dead-air cuts (silencedetect, no gap
   > 0.6 s survives), 3 hook text options (generated by Claude via draft.py's client), emphasis words, b-roll/cut points, preset,
   text timeline. Decisions go to Jev with code-side thresholds + heuristic fallback (pick preset = choice A-E with a no-match
   option; rank hooks = score; scroll-stop = existing hookscore). Generation (hook wording) = Claude. No keyword lists.
4. **Render** — `edit-render --edl <path>`: through render_clip / letterbox / existing overlay path, then the existing qa gate.
5. **Checks** (`edit-check`, each a named pass/fail with the measured value): duration inside STYLE range; first text on screen
   < 0.5 s; captions match speech (check_captions); no dead air > 0.6 s (silencedetect on the output); layout matches STYLE
   (band geometry); integrated loudness -14 LUFS +/- 1; no frozen video (freezedetect); required tags resolve via
   publish.final_text/tags_for per platform (`tiktok:@x` = TikTok only, bare tags = every platform — never hand-assemble captions);
   no text box intersects a tracked face.
6. **Critique loop** — contact sheet of the edit next to `ref-sheet.png`; Claude vision (Anthropic API, model from draft.py) scores
   10 criteria (hook strength, first-second pull, pacing vs refs, text legibility, text-on-face, layout match, grade/mood match,
   dead air, ending, overall "would PB Blake approve this"), returns JSON; fix the worst 3 by editing the EDL; re-render; max 3
   rounds; keep r1/r2 files beside the final. Write `critique.json` per round.
7. **Approval gate (hard, in code)** — an edit can reach the publish queue only with an approval record: chosen hook (1-3),
   approve/reject, grade 1-5, optional note. Campaign flag `edit_requires_approval` defaults TRUE for every campaign. Approve /
   reject also writes taste.py signals. `edit-approve --edit <id> --hook N --grade G [--note ...]` and `edit-reject`.
8. **Daily cap (in code)** — per-campaign `edit_daily_cap` (default 3); `edit-run` refuses to start past the cap and says so.
9. **One-shot** — `edit-run --campaign <id> [--moment <id> | --top N]`: plan -> render -> checks -> critique loop -> lands as
   "awaiting approval" with a review card (contact sheet + 3 hooks + check table). Approved edits enqueue through queue.py; the
   existing go-live gate (dry run) is untouched.
10. **Ledger** — `edit-grade` appends Yahia's grade + notes to a per-campaign ledger; a fault seen once becomes a line in the
    skill's playbook, seen twice becomes a new code check (follow content/SKILL.md exactly).
11. **Skill** — write `~/.claude/skills/clip-edit/SKILL.md` (front door: "edit clips for <campaign>", "edit room", "/clip-edit"):
    how Claude runs edit-run, shows Yahia the review card in chat, takes his hook pick + grade, calls edit-approve, ingests grades.
    Mirror motion-design SKILL.md's structure; keep it under ~150 lines.
12. Swift: no app changes unless edits cannot appear in the app's existing clip review list; if needed, keep them minimal and
    `swift build` + `swift test` must pass.
