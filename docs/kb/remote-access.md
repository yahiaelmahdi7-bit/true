# Decision: True on the web (phase 1 + drop)
Owner: cto · Last verified: 2026-10-08

**Decision.** Serve existing panes to Yahia's phone from True itself (it owns the PTYs), over the tailnet, instead of moving to a VPS. Spec: [SPEC.md "True on the web"](../../SPEC.md).

**Threat model.**
1. Reachable only through `tailscale serve` on the tailnet; never Funnel, never 0.0.0.0 — the server binds 127.0.0.1:8801.
2. Tailscale's `Tailscale-User-Login` header must equal the allowed login, else 403 (loopback clients can forge it, so the bind is what makes it trustworthy).
3. A paired-device **bearer token** is also required: 6-digit code (5 min, single use, 5 tries/min, **burned after 5 wrong guesses**) → 32-byte random token, stored server-side only as SHA-256, revocable in the sheet. The phone keeps the token in `localStorage` and sends `Authorization: Bearer` on `/api/*`; the WebSocket's first message is `{"auth":"<token>"}` (close 4401 if missing/invalid within 5 s; no PTY bytes before). **No cookie, on purpose:** cookies ignore ports, so a cookie would also be sent to the unrelated service on 8800 of the same `*.ts.net` hostname.
4. Exact `Host` (`<dns>:8444` or `<dns>`, kills DNS rebinding) on every request, and exact `Origin == https://<dns>:8444` on every state-changing request (`POST /pair`) and the WS upgrade. Every response carries `X-Frame-Options: DENY`, a strict CSP (no inline script), `nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`. Request head must arrive within 10 s overall (slowloris) and ≤ 16 KB; duplicate `Tailscale-User-Login`/`Host`/`Origin`/`Authorization` headers → 400; device file 0600 (created so), directory 0700.
5. Blast radius is "type into panes that already exist" **plus the phone drop (Run 24) plus server-proposed launches (Run 25, 5b)**: still no file browser, no raw-command endpoint; off by default.
5a. **Drop (Run 24).** `POST /api/drop` (≤ 200 MB, 120 s, ≥ 1 GB free, name sanitised to one safe component, never overwrites, quarantine xattr, never opened/executed; images → tray, rest → `~/Downloads`) and `POST /api/clip` (≤ 256 KB → pasteboard). The **only** relaxation of the Origin rule: on those two routes a request with *no* `Origin` is allowed when the bearer is valid (needed for the iOS Shortcuts share sheet; a bearer isn't ambient, so no CSRF); a present Origin must still be exact, and every other route still requires it. The phone can read only the **tray** (`/api/shots/<id>`, id regex + must be in index.json) and a **push-only inbox** the Mac filled (`/api/inbox*`, 20 items, 24 h, 0700/0600, copies). **No route reads the Mac clipboard or a Mac path** (tested against `RemoteServer.routeTable`). Served files can't run script: images keep an image type; everything else (SVG/HTML/PDF) is `octet-stream` + `attachment`; all file responses add `Content-Security-Policy: sandbox`. The "Shortcut" token is a **send-only** paired device (`scope: dropOnly`): it is accepted on `POST /api/drop` and `POST /api/clip` only — every other route is 403 and the pane WebSocket closes 4401 — so it cannot read tabs, shots or the inbox. Devices paired before scopes existed load as `full`. Revoke it in the sheet. At most 2 drop uploads run at once (3rd → 503 + `Retry-After`). Residual risk: a stolen Shortcut token can write files to `~/Downloads` (quarantined) and set the Mac clipboard — Mac clipboard paste is the sharper edge, so revoke on loss. The token is copied with `org.nspasteboard.ConcealedType` and the clipboard is cleared on "Done" if it still holds it.
5b. **Hub + ⌘K (Run 25).** The phone can start work but never submits a command: `POST /api/route {text}` makes the *server* build the route (rules → Jev picks among code-built candidates → router), `POST /api/run {routeId}` runs only that. routeId is 128-bit random, single use, 2-min expiry, bound to the making device. Slot edits are accepted only if the value is in the server's candidate list. Allowed doors: new shell split, new Claude pane, seat, background builder, open project / new tab / wake / sleep seat; nothing types into an existing pane. Destructive routes need a server-armed `confirm`. 10 runs/min/device, 30 proposals/min/device. Everything launched is a visible Mac tab tagged "from iPhone" for 10 min. `~/.true/commandbar/remote.jsonl` (0600) logs device id + SHA-256 of text + route + result. Builder **Ack** writes `acked:true` to `meta.json` only after the id matches a builder the Hub already knows. Send-only Shortcut tokens get 403 on all of it.
6. Residual risk: localStorage is readable by any script on the origin (none inline; CSP forbids foreign ones); a stolen unlocked paired phone = shell access to open panes — revoke from the Mac sheet.

Consequences: Mac must be awake; the Mac PTY size stays authoritative.
